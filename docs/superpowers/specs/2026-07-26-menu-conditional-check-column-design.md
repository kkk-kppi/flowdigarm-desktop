# 菜单条件勾选列设计

## 目标

消除完全不包含可勾选菜单项的菜单左侧空白，同时保留含状态项菜单中文字和勾选图标的纵向对齐。

## 行为

- 当前打开菜单只要有任一顶层菜单项定义了 `checked` 字段，就为全部顶层菜单项保留统一的 18px 勾选列。
- `checked: false` 仍表示该菜单项可勾选，因此必须保留列，避免状态切换时文字左右跳动。
- 当前菜单没有任何 `checked` 字段时，不渲染 `.check` 占位元素，菜单文字从按钮正常的 8px 左内边距开始。
- 当前只有“视图”菜单定义勾选状态；“文件”“编辑”“插入”“格式”“工具”“帮助”不再产生空白勾选列。
- 不改变快捷键右对齐、子菜单箭头、禁用态、分隔线、键盘导航、焦点恢复和命令执行。
- 子菜单现有行为不变；本次只处理 `MenuDefinition.items` 顶层菜单项。

## 实现

- 在 `MenuBar.vue` 增加一个纯判定函数，使用 `items.some((item) => item.checked !== undefined)` 判断当前菜单是否需要勾选列。
- 仅当判定为真时，在该菜单的每个顶层按钮中渲染 `.check`。
- `.check` 现有 18px 宽度和勾选图标样式保持不变。
- 不修改 `MenuItem` 类型或 `createMainMenus` 数据结构。

## 测试

- 组件测试打开“编辑”菜单，确认菜单项内不存在 `.check`。
- 组件测试打开含 `checked: false` 项的“视图”菜单，确认所有顶层菜单项都有 `.check`，但 false 项内没有勾选图标。
- 将状态改为 `checked: true` 时，确认同一列显示 `check` 图标，且列数量不变。
- 运行 `tests/component/MenuBar.test.ts`、完整 Vitest、生产构建和相关 Chromium 菜单测试。

## 验收标准

- “编辑”菜单的“撤销”等文字前不再有 18px 空槽。
- “视图”菜单无论开关当前为开或关，所有顶层文字保持同一左起点。
- 勾选状态切换不会引起菜单文字水平位移。
