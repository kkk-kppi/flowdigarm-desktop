# 自适应窗口尺寸与状态恢复设计

## 目标

让桌面应用首次打开时依据当前显示器的可用工作区选择舒适、居中的窗口尺寸，并在后续启动时恢复用户上次使用的普通窗口位置、尺寸和最大化状态。

## 范围

- 面向 Windows 10/11 与 macOS 桌面环境，不考虑移动端窗口行为。
- 首次启动和保存状态不可用时执行自适应布局。
- 后续启动优先恢复用户状态。
- 不恢复全屏状态。
- 不改变当前最小化、最大化、关闭确认和未保存文档保护行为。

## 首次启动尺寸

以主显示器排除任务栏、Dock 和菜单栏后的可用工作区为计算基准。所有比例计算使用同一坐标体系，并在调用 Tauri 窗口 API 时正确处理显示器缩放比例。

```text
目标高度 = 可用工作区高度 * 0.9
目标宽度 = min(可用工作区宽度 * 0.9, 目标高度 * 1.6)
```

- `1.6` 对应 `16:10`，用于避免 `21:9`、`32:9` 等超宽屏上的初始窗口横跨几乎整个工作区。
- 常规或较窄的屏幕仍可使用接近 90% 的工作区宽度。
- 计算完成后，将窗口在可用工作区内水平和垂直居中。
- 继续以 `960 x 600` 逻辑像素作为期望最小尺寸。
- 如果工作区本身小于期望最小尺寸，优先保证窗口完整位于工作区内，不强行扩大到屏幕之外。
- 宽高比限制只适用于首次启动和异常回退。用户后续主动调整出的任何窗口比例都应原样保存和恢复。

例如，可用工作区为 `3440 x 1440` 时，首次窗口约为 `2074 x 1296`，而不是 `3096 x 1296`。

## 状态恢复

复用现有 SQLite `window_state` 数据和 `WindowState` 仓储方法，不引入 `tauri-plugin-window-state` 或另一份状态文件。

保存内容包括：

- 普通窗口左上角物理坐标，用于映射虚拟桌面中的显示器位置；
- 普通窗口逻辑宽度和高度，用于在 DPI 变化后保持接近一致的视觉尺寸；
- 是否最大化；
- 更新时间。

恢复顺序为：

1. 读取已保存状态。
2. 校验尺寸为有限正值，并满足当前应用可显示的边界条件。
3. 检查保存矩形是否与任一当前显示器的可用工作区至少保留 `64 x 40` 逻辑像素的可见区域，确保窗口可以被识别和拖回。
4. 状态有效时先恢复普通位置和尺寸，再恢复最大化状态。
5. 状态缺失、损坏、完全位于屏幕外或对应显示器已断开时，执行首次启动自适应布局。

恢复用户状态时不重新套用 `16:10` 限制。若保存尺寸大于当前工作区，只缩小到当前工作区可容纳的范围；若位置部分越界，则移动到最近的有效工作区内。

## 保存时机

窗口协调逻辑位于 Rust/Tauri 层，避免依赖 WebView 完成初始化或关闭。

- 移动和缩放普通窗口时更新内存中的候选状态。
- 对连续窗口事件做短时防抖后写入 SQLite，避免拖动期间频繁写库。
- 最大化时保存 `maximized = true`，但保留最大化前的普通窗口位置和尺寸，不能用最大化边界覆盖普通边界。
- 从最大化恢复后，继续跟踪新的普通窗口边界。
- 关闭请求、正常退出和主窗口销毁路径应尽力刷新最新候选状态。
- 状态保存失败不得阻止窗口操作或应用关闭，只记录可诊断错误。

## 启动流程

主窗口在初始布局完成前保持隐藏，避免先显示固定配置尺寸、随后跳到恢复位置。

1. 初始化 SQLite 持久化状态。
2. 获取主窗口和当前显示器信息。
3. 恢复有效状态，或计算首次自适应尺寸。
4. 设置普通窗口位置和尺寸。
5. 按保存状态决定是否最大化。
6. 显示并聚焦窗口。
7. 启用窗口状态事件监听和防抖保存。

数据库不可用、显示器查询失败或窗口 API 调用失败时，应用仍应使用 Tauri 配置中的安全默认尺寸启动，不因窗口状态功能退出。

## 组件边界

- `src-tauri/src/lib.rs`：接入启动恢复、事件监听和持久化协调，不承载尺寸计算细节。
- Rust 窗口状态协调模块：负责初始尺寸计算、状态校验、显示器回退、普通边界跟踪和保存调度。
- `src-tauri/src/persistence/sqlite_repository.rs`：继续作为窗口状态的唯一持久化实现；现有读写接口保持职责不变。
- `src-tauri/tauri.conf.json`：保留安全默认尺寸，并将主窗口初始设置为隐藏，待布局完成后显示。
- 前端 `TauriWindowController`：继续处理标题栏命令和未保存文档关闭确认，不承担初始布局计算。

## 错误与边界处理

- 多显示器：有效保存状态在原显示器工作区恢复；显示器缺失时回退到主显示器。
- 任务栏或 Dock 位置变化：按当前可用工作区夹取，而不是沿用旧工作区边界。
- DPI 变化：保存和恢复时明确区分逻辑尺寸与物理尺寸，避免跨缩放显示器后尺寸放大或缩小。
- 状态损坏：拒绝负数、零尺寸、不可表示数值和完全不可见的位置。
- 数据库降级：跳过持久化，执行安全默认或自适应布局，应用其余功能继续可用。
- 最大化状态：恢复最大化但不恢复全屏；最小化状态永不跨启动恢复。

## 测试

- 单元测试首次尺寸计算：`16:9`、`16:10`、`21:9`、`32:9`、小工作区和高 DPI 输入。
- 单元测试状态校验与夹取：有效单屏、多屏、断开的副屏、部分越界、完全越界和超大保存尺寸。
- 单元测试最大化状态不覆盖最后普通窗口边界。
- Rust 仓储测试继续覆盖窗口状态 SQLite 往返，并补充无效状态在协调层的拒绝测试。
- 集成验证首次启动窗口隐藏期间无可见跳动，最终尺寸、位置和居中结果符合计算。
- 手工验证普通窗口关闭后恢复、最大化关闭后恢复、任务栏位置变化、拔除副屏和不同 DPI 显示器切换。
- 运行 `cargo test --locked --manifest-path src-tauri/Cargo.toml`、`pnpm test`、`pnpm build` 和 `git diff --check`。

## 验收标准

- 首次启动窗口完整位于主显示器可用工作区并居中。
- 常规屏初始窗口充分利用空间，超宽屏初始窗口宽高比不超过 `16:10`。
- 后续启动恢复上次普通位置、尺寸和最大化状态，不恢复最小化或全屏。
- 用户主动设置的超宽窗口可在后续启动原样恢复。
- 保存显示器不存在或状态无效时，窗口不会出现在屏幕外，而是回退到主显示器自适应布局。
- 窗口状态持久化失败不阻止应用启动、编辑或关闭。
